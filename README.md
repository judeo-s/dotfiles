# Oni's dotfiles

A snapshot of my Neovim, Hyprland + Caelestia desktop, Foot, Zsh + Starship,
and coordinated application themes. Intended for **Arch Linux and Arch Linux ARM**.

## Install on a new VM or machine

Install Arch/Arch ARM and suitable graphics drivers first. Run the following as
your normal user with sudo access, **not as root**:

```bash
sudo pacman -Syu --needed git python
git clone https://github.com/YOUR-USERNAME/dotfiles.git ~/Documents/github/dotfiles
bash ~/Documents/github/dotfiles/install.sh
```

For the original Apple M4 / VirGL VM, use:

```bash
bash install.sh --graphics virgl --monitor-mode '1920x1080@60'
```

For physical hardware:

```bash
bash install.sh --graphics native
```

`auto` (the default) preserves an existing machine's graphics choice; on a new
machine it detects VirGL through `glxinfo`. Detection may not work from a TTY;
use `--graphics virgl` explicitly for that VM. The workaround is scoped to
Caelestia; it fixes missing GLSL 330 panel backgrounds when Qt selects OpenGL 2.1.

The installer performs a full Arch upgrade, installs the desktop and development
dependencies, bootstraps Paru if needed, installs Caelestia from the AUR, backs up
existing configs, copies these configs, and restores Neovim plugins from the lockfile.
Missing plugins are explicitly installed, and plugin task failures stop the installer
rather than silently reporting success.
AUR builds are interactive and may take time. Package checksums and dependency
checks remain enabled. The two ARM dependency adaptations are in `scripts/patch-aur.py`.
Python's native compiler is explicitly selected to avoid Arch ARM's unavailable
distcc compiler path. Build recipes are fetched from the AUR, so review their prompts.

### Activate the desktop

Log out and select Hyprland in your display manager. The included Zsh/Bash login
profiles also use **UWSM** to start Hyprland from an eligible TTY login. If you
prefer a display manager exclusively, remove that block from your login profile.

Optional steps, depending on how the base system was installed:

```bash
sudo systemctl enable --now NetworkManager
chsh -s /usr/bin/zsh
```

The installer does not change networking, bootloader, GPU drivers, or your login
shell automatically. `--set-shell` opts into changing the login shell.

Start or restart Caelestia manually inside Hyprland:

```bash
sh ~/.config/caelestia/start.sh
sh ~/.config/caelestia/start.sh -r
```

For wallpaper-based colors:

```bash
caelestia wallpaper -f "$HOME/Pictures/Wallpapers/deadsec-1.jpg"
caelestia scheme set -n dynamic -m dark -v vibrant
```

The snapshot restores the selected wallpaper (`deadsec-4.jpg`) using the new
machine's home path. It includes the current generated palette and application themes;
changing the wallpaper may regenerate them. Profile images are optional: put one
at `~/.face` if desired. No personal profile image is exported.

## Useful installation options

```bash
# Preview files to be installed; no package or config changes
bash install.sh --dry-run

# Already have dependencies, or using another Linux distribution
bash install.sh --config-only --skip-plugins

# Only the editor, keeping an existing desktop
bash install.sh --config-only --only nvim

# Custom display scale
bash install.sh --graphics native --monitor-scale 1.5
```

Partial groups: `desktop`, `nvim`, `shell`, `themes`. Partial installs require
`--config-only`; otherwise the full package set would still be installed.
Config-only installation needs Python 3.11+. Neovim requires a compatible modern
version; this snapshot was verified on **Neovim 0.12.5**, **Hyprland 0.56.2 (Lua)**,
**Caelestia 2.5.0**, **Caelestia CLI 1.1.3**, and **Foot 1.28**. These are reference
versions, not instructions to downgrade a rolling-release distribution.

## Machine-specific configuration

- `~/.config/hypr/machine.lua`: monitor mode/scale, generated by the installer.
  On a fresh installation the mode is `preferred` and scale is `1`, rather than
  forcing the original VM resolution. Reinstallation preserves this file unless
  `--monitor-mode` or `--monitor-scale` is supplied; overrides retain other fields.
- `~/.config/caelestia/machine.env`: enables/disables the VirGL workaround.
- `~/.config/caelestia/monitors/`: per-output overrides; the original `Virtual-1`
  entry is empty. Create overrides for your output names if needed.
- `hypr/monitors.lua` and `hypr/monitors.conf` preserve the current nwg-displays
  output as reference. The main Lua config does not automatically load them;
  portable installations use `machine.lua` instead of forcing `Virtual-1` settings.
- GTK/Qt themes are included. `qtengine/config.json` references the optional
  Darkly style; installing QtEngine/Darkly separately is required to use it.
- `packages/current-versions.txt` records the original system for reference; the
  installer uses the curated package lists, not this entire system inventory.

Configuration paths assume the usual `~/.config` and `~/.local/state` layout.
The installer rejects nonstandard `XDG_CONFIG_HOME`/`XDG_STATE_HOME` settings
instead of installing configs into paths your applications will not read.
Foot retains Zsh, 90% background opacity, blur, and the current color palette.

## Neovim

Includes the random-ASCII Alpha dashboard, current plugin lockfile, Tree-sitter
0.12 compatibility adapter, LSP/completion, formatting, search, Git, and editing tools.
The plugin lockfile is intentionally tracked even though the original Neovim repo
ignored it. No nested Git checkout, sessions, typing stats, or caches are included.
The portable snapshot also supplies `.prettierrc.json` (the filename expected by
the formatter) and prevents a failed headless Lazy bootstrap from waiting for input.

After installation:

```vim
:Lazy restore
:checkhealth
:Mason
```

The installer provides common formatters and servers. Additional tools such as
JDTLS, CMake language servers, Rust tooling, and Beautysh are language-dependent;
install those you use via Mason, the distribution, or their documented setup.
Mason binary availability can differ on ARM.

## Backups and rollback

Existing files/directories are moved into
`~/.local/share/dotfiles-backups/<timestamp>/original/` before replacement.
The installer prints a `manifest.json` path. To roll back:

```bash
python scripts/deploy.py --restore "$HOME/.local/share/dotfiles-backups/TIMESTAMP/manifest.json"
```

Rollback saves any post-install edits in the backup's `after-install/` folder.
It checks the complete backup before changing files and records restore progress.
Backups are incremental per installation; restore the most recent one first.
Packages installed by Pacman/AUR are not removed by config rollback.
No running compositor is restarted by installation or rollback.

## Refresh the GitHub snapshot

Configs are **copied**, not symlinked, so Caelestia's theme generator cannot
rewrite this Git checkout. To refresh after editing your live configs:

```bash
python scripts/snapshot.py --refresh --wallpapers
python scripts/check.py
python -m unittest discover -s tests -v
git diff
```

Review deletions separately: refresh updates the allowlisted files but deliberately
does not delete repository files missing from your live setup.
Portable adaptations (home paths, monitor settings, guarded shell initialization,
and selectable graphics workaround) are reapplied on each snapshot.

The snapshot includes app **themes only** for Discord variants, Spicetify, and Zed, never
their profiles. Browser profiles, SSH keys, OpenCode credentials/configuration,
shell histories, dconf databases, notification history, and app usage databases
are excluded. Wallpapers retain their original ownership; included downloads
are not relicensed by this repository. Omit `--wallpapers` on future snapshots
and remove `wallpapers/` before publishing if you prefer not to redistribute them.

## Publish to GitHub

Create an empty GitHub repository, replace the placeholders, then:

```bash
git add .
git commit -m "Add desktop and Neovim dotfiles with installer"
git remote add origin https://github.com/YOUR-USERNAME/dotfiles.git
git push -u origin main
```

Before committing, review `git status` and `git diff --cached`.
GitHub Actions validates installer syntax, Lua/Zsh, JSON/TOML, and backup/restore behavior.
